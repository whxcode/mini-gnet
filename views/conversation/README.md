# 对话记录与流式显示

角色统一使用“图标 + 角色名 + 名称”的标题，正文与标题分行，相邻消息之间留空行：

- 绿色 `● user · 当前用户名`：用户提交的问题。
- 紫色 `✦ assistant`：模型的完整回答。
- 黄色 `⚙ tool · run_python / run_bash`：工具调用参数和执行结果。
- 青色 `◆ system`：启动信息、重试、取消等运行提示。
- 红色 `! error`：请求或任务失败。

这里的 system 是给用户看的运行提示，不会把整段内部系统提示词刷到屏幕上。

## 数据怎么走

1. `internal/app/app.go` 的 `Chat` 直接启动 Agent，创建消息通道。
2. `internal/app/agent.go` 的 `readAnswer` 主动调用 `stream.Next()` 读取文字，并发送 `Delta` 消息。
3. `stream.go` 从通道读取消息，在底部显示状态标题和最新两行文字。
4. 收到完整 `Message` 后，用 `tea.Println` 把消息放入上方记录，并清空预览。
5. Agent 退出后，应用关闭通道，界面清除预览；应用等待 Agent 结束后再接受输入。

网络请求与工具执行由应用启动的工作协程顺序执行，Bubble Tea 不再负责启动业务。
界面内部仍有框架规定的 `Cmd`，只负责接收显示消息和刷新动画。
不能在 `Update` 中等待网络，也不能在工作协程里同时用 `fmt.Println` 抢占终端输出。

生成过程中按 Ctrl+C 会取消本轮任务，等待任务退出后返回输入框；在输入框中按 Ctrl+C 则退出程序。
如果生成中断，已经收到的文本会标为“未完成”，避免看起来像完整回答。

界面只是显示层。发送给模型、工具以及保存到 JSONL 的原始消息格式不受颜色和预览截断影响。
非交互管道只打印完整消息，不启用光标移动或预览刷新。
