# 对话记录与流式显示

角色统一使用“图标 + 角色名 + 名称”的低饱和色标题；正文使用统一浅色并缩进，相邻消息之间留空行：

- 柔和绿色 `● user · 当前用户名`：用户提交的问题。
- 淡紫色 `✦ assistant`：模型的完整回答。
- 暖黄色 `⚙ tool · run_python / run_bash`：工具调用参数和执行结果。
- 灰青色 `◆ system`：启动信息、重试、取消等运行提示。
- 淡红色 `! error`：请求或任务失败。

这里的 system 是给用户看的运行提示，不会把整段内部系统提示词刷到屏幕上。

会话标题和状态位于顶栏，模型与目录使用次要颜色。单个会话不重复显示标签栏，多会话才显示切换状态。
正文与输入区之间保留间距；输入框有独立底色和圆角边框，下方只显示常用快捷键，其他操作通过 `/help` 查看。
区块按实际内容增长，输入框不固定在终端底部。

## 数据怎么走

1. `internal/app/app.go` 的主循环准备任务后直接调用 `go session.RunTask(job)`，随即继续读取输入。
2. `internal/app/agent.go` 的 `RunTask` 顺序请求模型、读取流、保存回答及执行工具。
3. 任务直接更新所属 `Session` 的文字、状态与完整消息，不通过 channel 中转，也不直接输出到终端。
4. `internal/app/terminal.go` 定时读取当前会话快照，显示记录、实时文字和始终可用的输入框。
5. 切换只改变查看的会话。后台任务结束后标记新结果，直到用户切回查看。

`message.go` 提供通用消息格式；`stream.go` 保留独立的单轮输出组件，但多会话应用使用 `terminal.go`。
按 Ctrl+C 只停止当前运行中的任务；当前空闲时请求退出，存在其他运行中任务则显示退出确认。
如果生成中断，已经收到的文本标为“未完成”，不会作为完整回答保存给模型。

界面只是显示层。发送给模型、工具以及保存到 JSONL 的原始消息格式不受颜色和预览截断影响。
非交互管道只打印完整消息，不启用光标移动或预览刷新。
