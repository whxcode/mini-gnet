# 当前工作目录的 Agent 配置

```text
.agent/
├── AGENTS.md
└── skills/
    └── code-review/
        └── SKILL.md
```

程序以界面显示的工作目录（配置中的 `projectDir`）为起点；未配置时使用启动目录，不使用可执行文件所在目录。

## 发现规则和技能

- `.agent/AGENTS.md`：正文追加到基础系统提示词之后。
- `.agent/skills/<技能目录>/SKILL.md`：先提取 YAML 中的 `name`、`description` 和文件位置，作为系统提示词中的技能目录。此时不注入正文，不执行脚本。
- 只扫描直接子目录，按目录名排列；缺少整个目录或某个 `SKILL.md` 时跳过。
- YAML 支持带引号的字符串以及 `>`、`|` 多行简介。其他扩展字段不改变工具权限，也不会自动配置执行环境。
- 格式错误、重复技能名或文件读取失败时，返回具体文件路径和原因。技能文件上限为 1 MiB。

最小技能文件：

```markdown
---
name: code-review
description: 审查 Go 代码变更，检查错误处理和边界条件。
---

# 审查步骤

1. 查看 Git 变更。
2. 阅读相关函数与调用位置。
3. 说明发现的问题、位置和原因。
```

推荐名称使用不含空格的短名称，如 `code-review`；`--clear` 是命令保留参数。加载时匹配 YAML 的 `name`，不要求它与文件夹同名。

创建会话时保存一份系统提示词到 JSONL。每项任务开始时重新读取规则与摘要，替换本次请求中的系统提示词；同一任务的多轮请求复用这份内容。历史文件的首条 system 保留创建时快照。

## 手动选择

输入 `/skills` 打开菜单，上下选择，Enter 确认，Esc 返回并保留原选择。也可以直接输入：

```text
/skills code-review
检查这次 Git 修改，只分析，不修改代码。
```

选择后不立即请求模型，输入框上方显示下一条使用的技能。提交普通问题时，把问题、技能说明和资源目录合成一条正常 `user` 消息，沿原来的任务队列写入历史。

- 待选技能只属于当前会话，切换会话互不影响。
- 成功入队后清除待选状态；空问题、队列满或加载失败不会丢掉原选择。
- `/skills --clear` 仅取消尚未提交的选择，不删除历史中的正文。
- 选择时读取正文，已提交的任务保存当时内容；文件更新后重新选择即可。
- 管道输入中的 `/skills` 输出名称和简介，`/skills <名称>` 与交互模式行为相同。

## 模型自动加载

用户直接提问时，模型从系统提示词中的摘要判断是否有匹配技能。需要时调用内置工具：

```json
{"name":"code-review"}
```

工具名为 `load_skill`。它按名称读取文件，返回 `name`、`description`、`path`、`directory` 和 Markdown `content`；结果沿原有流程存成普通 `tool` 消息，模型下一轮据此继续完成任务。

加载正文不等于执行任务，也不会自动运行技能附带的脚本。正文里的相对资源路径以返回的 `directory` 为起点，需要时由模型使用已有工具读取。能否主动选对技能仍取决于模型，程序不强制为每个问题选技能。

## 历史记录约定

当前采用简单方案：手动附加的正文和工具返回的正文都完整保留在正常历史里，不做任务结束后的剥离、过滤或清理。后续请求和 `/resume` 都会带上它们。

下一条提问不再自动附加上次待选技能，但历史内容仍可能影响模型。想开始不带旧技能正文的对话，使用 `/new`；项目规则和可用技能摘要仍会正常加载。

## 手动验证

在项目根目录运行 `go run main.go`：

1. 输入 `/tools load_skill`，确认技能加载工具已注册。
2. 输入 `/skills`，确认能看到 `code-review`；Esc 返回。
3. 输入 `/skills code-review`，再输入“检查这次 Git 修改，只分析，不修改代码”。观察 user 消息中包含技能正文。
4. 再提一个普通问题，观察这次 user 消息不再附加正文，之前的正文仍保留在历史中。
5. 输入 `/new`，再问“请使用 code-review 技能检查这次修改，只分析”。观察模型是否调用 `load_skill`，收到结果后是否继续检查。
6. 输入 `/resume` 恢复旧会话，确认技能内容随聊天记录保留。

自动测试使用本地模拟模型，验证消息结构、加载结果、多轮循环、会话隔离及恢复，不调用付费接口。真实模型是否正确采用说明，需要通过上述步骤观察。

## 代码阅读顺序

手动入口：`internal/command/skills.go` → `internal/skill.Load` → `Session.SelectSkill` → `Session.Enqueue` → 原有 Agent 和历史记录流程。

自动入口：模型发出 `load_skill` → `tools.Registry.Execute` → `tools/skill.Tool.Execute` → 同一个 `internal/skill.Load` → 原有 tool 历史与下一轮请求。

`internal/skill/catalog.go` 负责解析，`internal/skill/load.go` 负责按名称读取与组装手动提问，`views/commands/skills.go` 只处理菜单。
