# 当前工作目录的 Agent 配置

```text
.agent/
├── AGENTS.md
└── skills/
    └── code-review/
        └── SKILL.md
```

程序以界面显示的工作目录（配置中的 `projectDir`）为起点；未配置时使用启动目录，不使用可执行文件所在目录。

## 发现规则和技能

- `.agent/AGENTS.md`：正文追加到基础系统提示词之后。
- `.agent/skills/<技能目录>/SKILL.md`：先提取 YAML 中的 `name`、`description` 和文件位置，作为系统提示词中的技能目录。此时不注入正文，不执行脚本。
- 只扫描直接子目录，按目录名排列；缺少整个目录或某个 `SKILL.md` 时跳过。
- YAML 支持带引号的字符串以及 `>`、`|` 多行简介。其他扩展字段不改变工具权限，也不会自动配置执行环境。
- 格式错误、重复技能名或文件读取失败时，返回具体文件路径和原因。技能文件上限为 1 MiB。

最小技能文件：

```markdown
---
name: code-review
description: 审查 Go 代码变更，检查错误处理和边界条件。
---

# 审查步骤

1. 查看 Git 变更。
2. 阅读相关函数与调用位置。
3. 说明发现的问题、位置和原因。
```

推荐名称使用不含空格的短名称，如 `code-review`。加载时匹配 YAML 的 `name`，不要求它与文件夹同名。

创建会话时保存一份系统提示词到 JSONL。每项任务开始时重新读取规则与摘要，替换本次请求中的系统提示词；同一任务的多轮请求复用这份内容。历史文件的首条 system 保留创建时快照。

## 行内技能引用

直接在同一条提问里引用技能：

```text
请使用 /skills{code-review} 检查这次 Git 修改，只分析，不修改代码。
```

输入框会把完整引用显示成紫色 `◆ code-review` 标签。也可以输入“请使用 /”，从候选中选中技能：↑↓ 或 Tab 选择，Enter 确认，继续输入问题后再按 Enter 发送。Esc 只关闭候选，不丢草稿。

句首 `/` 提供带类型标记的命令和技能候选；正文中只提供技能候选。路径、URL、行内代码和代码围栏里的斜线不触发引用。左右键跨过整个标签，Backspace/Delete 整块删除；Shift+方向键可以选择标签和文字。

- 引用属于这条输入，不再保存“下一条使用某技能”的会话状态。
- `/skills` 和 `/skills <名称>` 只查看简介与引用写法；`/skills --clear` 不再用于设置或清除状态。
- 提交时任务复制 `kind/value` 片段；后续编辑或切换会话不影响它。
- 任务轮到执行时才读取正文，排队期间修改技能文件会生效；同任务后续多轮请求复用首次组装的消息。
- 同一条提问可以引用多个技能，重复名称只附加一次正文。
- 不完整引用在提交时提示错误并保留草稿；未知技能或读取失败在任务执行时报告，不继续请求模型。
- 管道直接支持同样的 `/skills{名称}` 语法。

当前只实现文字和技能，文件、工具引用暂未接入。

## 模型自动加载

用户直接提问时，模型从系统提示词中的摘要判断是否有匹配技能。需要时调用内置工具：

```json
{"name":"code-review"}
```

工具名为 `load_skill`。它按名称读取文件，返回 `name`、`description`、`path`、`directory` 和 Markdown `content`；结果沿原有流程存成普通 `tool` 消息，模型下一轮据此继续完成任务。

加载正文不等于执行任务，也不会自动运行技能附带的脚本。正文里的相对资源路径以返回的 `directory` 为起点，需要时由模型使用已有工具读取。能否主动选对技能仍取决于模型，程序不强制为每个问题选技能。

## 历史记录约定

当前采用简单方案：手动附加的正文和工具返回的正文都完整保留在正常历史里，不做任务结束后的剥离、过滤或清理。后续请求和 `/resume` 都会带上它们。

下一条提问只处理自己的引用，但历史内容仍可能影响模型。想开始不带旧技能正文的对话，使用 `/new`；项目规则和可用技能摘要仍会正常加载。

## 手动验证

在项目根目录运行 `go run main.go`：

1. 输入 `/tools load_skill`，确认技能加载工具已注册。
2. 输入 `/skills` 查看目录；随后输入“请使用 /”，确认技能候选出现，Esc 关闭。
3. 输入“请使用 /sk”，Enter 确认技能标签，接着输入“ 检查这次 Git 修改，只分析，不修改代码”，再次 Enter 发送。界面显示简短问题，JSONL 的 user 内容包含正文。
4. 再提一个普通问题，观察这次 user 消息不再附加正文，之前的正文仍保留在历史中。
5. 输入 `/new`，再问“请使用 code-review 技能检查这次修改，只分析”。观察模型是否调用 `load_skill`，收到结果后是否继续检查。
6. 输入 `/resume` 恢复旧会话，确认技能内容随聊天记录保留。

自动测试使用本地模拟模型，验证消息结构、加载结果、多轮循环、会话隔离及恢复，不调用付费接口。真实模型是否正确采用说明，需要通过上述步骤观察。

## 代码阅读顺序

手动入口：输入框片段 → `Session.EnqueueInput` → `Task.NewInput` 复制 → `Agent.Run` → `query.Input.Resolve` 加载正文 → 原有历史和模型循环。

自动入口：模型发出 `load_skill` → `tools.Registry.Execute` → `tools/skill.Tool.Execute` → `internal/skill.Load` → 原有 tool 历史与下一轮请求。

输入结构和具体职责见 `internal/query/README.md`。手动与自动都调用同一个技能读取函数。
